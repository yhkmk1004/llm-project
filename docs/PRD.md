## 3. 기능

### 3-1. 추가할 기능

- 브라우저 캐시 활용해서 각종 선택들이 창을 닫았다가 다시 열 때도 유지되도록
- 키워드 동적 업데이트 창
    - 태그 형태로 관리 (저장 필요)
- 정렬 (저장 필요)
    - 키워드 정렬
        - 알파벳순 오름차순/내림차순
        - 직접 정렬 → 키워드 드래그해서 순서 변경
    - 할인 소식 정렬
        - 종료일 기준 오름차순으로 가장 먼저 끝나는 항목이 가장 위에 오도록
        - 시작일 기준 내림차순으로 가장 최근 시작한 할인 항목이 가장 위에 오도록
- 카테고리(그룹화)
    - 키워드 태그에 따라 할인 소식들이 칸반보드 각 열을 차지하도록
- 키워드 개선 에이전트 (브라우저 안에서 도는 작은 루프)
    - 관찰: LLM이 걸러진 글과 남은 글을 비교해 엉뚱한 글이 섞인 원인을 찾음 (예: "청소기"에 해외 직구 기사가 섞임)
    - 제안: 제외어 추가 또는 키워드 구체화를 제안 (예: 제외어 '해외' 추가)
    - 실행: 사용자가 승인하면 페이지 필터 규칙을 고치고 필터를 다시 돌림 → 바뀐 결과를 보고 다시 관찰
    - 승인한 제외어·키워드는 저장 (브라우저 캐시)
    - 제약
        - 페이지 필터만 고칠 수 있음. 수집 키워드(repo 설정)는 페이지에서 못 고치므로, Google 뉴스 수집까지 바꾸려면 사용자가 repo 설정을 직접 수정
        - Gemini Nano가 한국어를 바로 못 받아서 제목을 영어로 번역해 판단 → 제안한 단어를 다시 한국어로 번역한 뒤, 실제로 걸러진 글 제목에 들어 있는지 코드로 확인하고 없으면 제안을 버림
        - 한 번에 넣을 수 있는 글자 수가 제한돼 있어 글을 나눠서 판단
        - 작은 모델이라 제안이 틀릴 수 있음 → 사용자 승인 없이는 아무것도 바꾸지 않음

### 3-2. 이번 프로젝트에서 제외할 기능

- 알림 설정
- RSS로 간단히 수집 불가능한 페이지들에 대한 우회법
- 다크모드
- LLM 자동 실행 (Actions 수집 직후 자동 판단)
    - Chrome built-in LLM은 브라우저 안에서만 도는 JavaScript API라 Actions 서버에서 호출할 수 없음
    - Actions에 headless Chrome을 띄우는 방법은 저장 공간 22GB·RAM 16GB가 필요하고, 실행할 때마다 모델을 다시 받아야 해서 비현실적
    - 페이지에서 자동으로 돌려도 모델 첫 다운로드는 버튼 클릭 같은 사용자 동작이 필요
    - → 이번에는 버튼을 눌러 판단하는 방식으로 진행

### 3-3. Flow: Actions 수집 + LLM 정리

> GitHub Actions(15분마다) → RSS 수집·중복 제거 → data.json 커밋 → 웹페이지가 data.json 읽기 → 키워드 필터 → Chrome built-in LLM 판단 → 화면 표시
> 
1. 수집 설정
    - 수집할 키워드와 RSS 주소를 repo 설정 부분에 적어둠
    - 강사가 템플릿을 제공하고, 수강생은 키워드만 바꿈
2. 자동 수집 (GitHub Actions)
    - `collect.yml`이 15분마다 `collect.py`를 실행 — GitHub 서버에서 돌아서 내 컴퓨터가 꺼져 있어도 수집됨
    - 뽐뿌 핫딜: RSS feed만 사용 (목록 페이지는 403으로 막혀 있어 우회하지 않음)
    - Google 뉴스: 키워드별 검색 RSS (`news.google.com/rss/search?q=키워드&hl=ko&gl=KR&ceid=KR:ko`)
    - 브라우저가 아닌 서버에서 가져오므로 CORS 문제가 없음
    - 참고: 15분 주기는 정확히 지켜지지 않고 밀리는 날이 있음 → 뽐뿌 글 일부를 놓칠 수 있지만 개인 tracker로는 감수할 수준
3. 정리 후 저장
    - 링크 기준 중복 제거, 같은 보도자료 묶기, 7일 지난 글 정리
    - 결과를 `data.json`으로 저장하고 Actions가 repo에 자동 커밋
4. 화면에서 불러오기
    - 웹페이지([localhost](http://localhost) 또는 GitHub Pages)가 `data.json`을 읽어옴
5. 1차 필터 — 키워드
    - 제목에 관심 키워드가 들어간 글만 남김
    - 키워드만으로는 엉뚱한 글이 섞인다는 걸 보여주는 단계 (예: "청소기" → 해외 할인 기사)
6. 2차 필터 — Chrome built-in LLM
    - 버튼을 누르면 브라우저 안에서 페이지에 입력한 관심사에 맞는 글인지 판단 (자동 실행이 빠진 이유는 3-2 참고)
    - 이미 판단한 글은 결과를 캐시해 다시 판단하지 않음
    - 한국어를 바로 못 받으면 Translator API로 영어로 바꾼 뒤 Prompt API로 판단
    - 남은 글을 키워드별 칸반 열에 표시하고 원문 링크 제공 (정렬은 3-1 기준)
7. 키워드 개선 루프 — 에이전트 단계
    - 2차 필터 결과를 보고 LLM이 제외어 추가나 키워드 구체화를 제안 → 사용자가 승인하면 5–6단계를 다시 돌림 (자세한 내용은 3-1 참고)
    - 1–6단계는 정해진 순서대로 흐르는 워크플로이고, 이 단계에서는 LLM이 결과를 보고 다음 행동을 정함 → 워크플로와 에이전트의 차이를 보여주는 단계
